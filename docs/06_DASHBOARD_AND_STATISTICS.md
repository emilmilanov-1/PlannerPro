# Milestone 6 — Dashboard и статистика

## Цел

Този етап превръща записаните задачи и графикови блокове в разбираеми показатели. Всички стойности идват от SQLite и се преизчисляват при всяко отваряне на страницата.

## Dashboard

Началната страница показва:

- брой активни задачи;
- задачи със срок днес;
- просрочени задачи;
- активни задачи с висок или критичен приоритет;
- следващ работен блок от запазения график;
- препоръчана задача, когато няма график;
- петте най-близки крайни срока;
- напредък по брой задачи;
- напредък по отчетено време.

Следващият блок се избира сред незавършените блокове, чийто край е в бъдещето. Ако няма такъв блок, приложението използва най-високия `PriorityScore` и след това най-близкия срок.

## Два различни показателя за напредък

### Напредък по задачи

```text
завършени задачи / всички задачи × 100
```

Тук всяка задача има еднаква тежест.

### Напредък по време

```text
изпълнени минути / прогнозни минути × 100
```

Този показател отчита реалния обем работа. Завършена задача от 15 минути не се третира като равна по обем на четиричасов проект.

Отложените задачи не участват в показателя по време, защото в момента не са част от активното натоварване.

## Статистика по статус

Показват се четирите възможни състояния:

- нови;
- в процес;
- завършени;
- отложени.

За всяко състояние се изчисляват брой и процент спрямо всички задачи.

## Статистика по приоритет

Разпределението по приоритет използва само активните задачи. Завършените задачи получават нисък активен приоритет от алгоритъма и включването им би изкривило резултата.

Показват се:

- нисък;
- среден;
- висок;
- критичен.

## Напредък по категории

За `Study`, `Work`, `Personal` и `Other` се показват:

- брой задачи;
- изпълнени и прогнозни минути;
- процент напредък по време.

Категория без задачи остава видима с нулеви стойности. Така структурата на визуализацията не се променя непредвидимо.

## Седемдневен обзор

Графиката показва следващите седем календарни дни, започвайки от днес. За всеки ден се изчисляват:

- планирани минути;
- изпълнени минути;
- брой работни блокове.

Височината на колоната се сравнява с най-натоварения ден в периода. Вътрешната зелена колона показва изпълнената част.

Визуализацията използва само HTML и CSS. Това премахва зависимостта от външна JavaScript chart библиотека и прави демонстрацията надеждна офлайн.

## Синхронизиране със задачите

Когато задача бъде маркирана като завършена:

1. `CompletedMinutes` става равно на `EstimatedMinutes`;
2. `CompletedAtUtc` се попълва;
3. свързаните `ScheduleBlock` записи получават `IsCompleted = true`;
4. Dashboard и статистиката показват новите стойности при следващото зареждане.

Ако задачата бъде върната в активен статус, нейните блокове отново се маркират като незавършени.

## Празни състояния

- при липса на задачи статистиката предлага създаване на първа задача;
- при липса на графикови блокове седмичният обзор предлага отваряне на планера;
- при липса на активни задачи Dashboard показва завършено състояние;
- при липса на предстоящи срокове списъкът показва кратко обяснение.

## Какво да обясним на защитата

1. Данните се четат асинхронно чрез Entity Framework Core.
2. `AsNoTracking()` се използва за статистики, защото записите не се редактират.
3. ViewModel-ите съдържат готови стойности за показване, а Razor не прави заявки към базата.
4. Напредъкът по задачи и по време отговаря на различни въпроси.
5. Приоритетното разпределение включва само активните задачи.
6. Седмичната графика използва записаните `ScheduleBlocks`.
7. Завършването на задача веднага влияе на няколко показателя.

## Автоматични проверки

Тестовете проверяват:

- Dashboard с реална задача и следващ графиков блок;
- общ брой и висок приоритет;
- проценти по задачи и време;
- седмично изпълнено време;
- синхронизиране на блоковете при завършване на задача;
- коректно отчитане на изпълнените минути.
