# Milestone 4 — външен API за официални празници

## Цел

PlannerPro използва външни данни, за да разпознава националните празници в България. В Milestone 5 тези дати ще бъдат изключени от автоматично генерирания график.

Източникът е [Nager.Holidays API](https://nagerholidays.com/api), а използваният адрес е:

```http
GET https://nagerholidays.com/api/v4/Holidays/BG/{year}
```

`BG` е ISO 3166-1 alpha-2 кодът на България.

## Поток на заявката

```text
PlannerController
→ IHolidayApiClient
→ проверка на MemoryCache
→ HttpClient GET заявка
→ JSON от Nager.Holidays
→ System.Text.Json десериализация
→ HolidayDto[]
→ филтриране на националните празници
→ PlannerOverviewViewModel
→ Razor View
```

Controller-ът не знае URL адреса и не обработва JSON. Това е отговорност на `HolidayApiClient`.

## Typed HttpClient

Регистрацията е в `Program.cs`:

- base address към API v4;
- timeout от 10 секунди;
- `Accept: application/json`;
- `User-Agent: PlannerPro/1.0`;
- Dependency Injection чрез `IHolidayApiClient`.

Така `HttpClient` се управлява от `IHttpClientFactory`, вместо да се създава ръчно при всяка заявка.

## JSON модел

`HolidayDto` съдържа само полетата, които приложението използва:

| JSON поле | C# поле | Предназначение |
|---|---|---|
| `date` | `Date` | дата на празника |
| `name` | `Name` | име на празника |
| `countryCode` | `CountryCode` | код на държавата |
| `nationalHoliday` | `NationalHoliday` | дали важи национално |
| `holidayTypes` | `HolidayTypes` | типове като `Public` |

Неизползваните полета не се добавят в DTO, което запазва интеграцията проста.

## Асинхронност и CancellationToken

`GetHolidaysAsync` използва `await` за HTTP заявката и JSON десериализацията. `CancellationToken` идва от MVC заявката. Ако потребителят затвори страницата, ненужната външна операция може да бъде прекратена.

Когато отменянето идва от потребителя, exception-ът се предава към ASP.NET Core. Когато е изтекъл 10-секундният timeout на клиента, се включва резервният режим.

## Кеш

Успешните резултати се пазят 12 часа в `IMemoryCache`. Ключът съдържа държавата и годината:

```text
holidays:BG:2026
```

Втора заявка за същата комбинация не извиква външната услуга. В интерфейса се показва дали резултатът е дошъл от API или от кеша.

## Резервен режим

Следните проблеми не прекъсват страницата:

- HTTP грешка;
- липса на мрежа;
- timeout;
- невалиден JSON;
- празен JSON документ.

При проблем клиентът връща празен списък и разбираемо предупреждение. В Milestone 5 графикът ще продължи да се генерира без празници, вместо да хвърля необработена грешка.

## Валидация

- кодът на държавата трябва да съдържа точно две латински букви;
- кодът се преобразува автоматично до главни букви;
- годината трябва да е между 1970 и 2100;
- показват се само записи с `nationalHoliday: true`;
- празниците се сортират по дата.

## Какво да обясним на защитата

1. Използваме typed `HttpClient`, защото интеграцията има собствен адрес, timeout и заглавки.
2. DTO моделът съответства на нужните JSON полета.
3. Всички мрежови операции са асинхронни.
4. Кешът намалява повторните заявки и прави страницата по-бърза.
5. Външна услуга не трябва да може да спре цялото приложение, затова имаме fallback.
6. Интерфейсът `IHolidayApiClient` позволява истинският клиент да бъде заменен с тестов.

## Автоматични тестове

Тестовете използват контролиран `HttpMessageHandler` и не зависят от интернет. Проверяват:

- правилния v4 адрес и HTTP заглавки;
- JSON десериализацията;
- филтрирането и сортирането;
- кеширане без втора HTTP заявка;
- HTTP грешка;
- timeout;
- невалиден JSON;
- потребителско отменяне;
- невалиден код на държава.
