# Milestone 1 — MVC основа

## Какво създадохме

`PlannerPro.sln` е контейнерът, който обединява проектите. Той не съдържа бизнес логика, а помага на Visual Studio и `dotnet` да виждат системата като едно цяло.

`PlannerPro.Web` е ASP.NET Core MVC приложението:

- `Controllers` приемат HTTP заявки и избират отговор;
- `Views` са Razor шаблони, които генерират HTML;
- `Models` ще съдържат данните и правилата;
- `wwwroot` съдържа публичните CSS и JavaScript файлове;
- `Program.cs` конфигурира приложението и маршрутите.

`PlannerPro.Tests` е отделен xUnit проект. По-късно той ще проверява score алгоритъма и графика без браузър.

## Как работи MVC заявка

При адрес `/Tasks/Index`:

1. маршрутизацията намира `TasksController`;
2. изпълнява метода `Index()`;
3. `return View()` търси `Views/Tasks/Index.cshtml`;
4. Razor обработва шаблона и връща HTML.

Кратък отговор за защитата: controller управлява заявката, view показва резултата, а model носи данните и правилата.

## Защо имаме общ layout

`Views/Shared/_Layout.cshtml` съдържа общите части — заглавие, меню, footer, CSS и JavaScript. Всяка страница се поставя в `@RenderBody()`, затова навигацията не се копира.

## Какво нарочно още не работи

- бутоните за създаване и график са изключени;
- числата са placeholder стойности;
- няма база данни, форми и алгоритми.

Това не са дефекти. Milestone 1 доказва, че архитектурата, маршрутите, изгледите и общият дизайн работят. Следващият етап ще замени placeholder данните с реални записи от SQLite.

## Какво трябва да можем да покажем

- приложението се стартира;
- четирите страници се отварят;
- мобилното меню се свива;
- всеки URL се обработва от подходящ controller;
- изгледите споделят един layout.

## Локални портове

`Properties/launchSettings.json` задава адресите за разработка. Използваме фиксиран HTTP порт `5090` и HTTPS порт `7090`. Стойността `localhost:0` означава „избери произволен свободен порт“, но не се поддържа от Kestrel при binding към hostname `localhost` в използваната среда.
