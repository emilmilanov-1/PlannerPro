# PlannerPro

Курсов проект на тема **„Интелигентен помощник за планиране на задачи“**.

## Текущ статус

Проектът е завършен и подготвен за представяне:

- solution с уеб и тестов проект;
- четири основни страници;
- общ responsive layout и навигация;
- responsive визуален стил и навигация;
- модел `TaskItem` с валидация и работещ CRUD;
- Entity Framework Core и SQLite;
- migrations `InitialCreate` и `AddDeadlineCategory`;
- 10 демонстрационни задачи;
- търсене и филтри по статус, категория и приоритет;
- Dashboard с реални данни от базата;
- автоматичен `PriorityScore` от 0 до 100;
- четири нива на приоритет и пет срокови групи;
- разбираемо обяснение на всяка автоматична оценка;
- typed `HttpClient` към Nager.Holidays API v4;
- асинхронно зареждане на официалните празници в България;
- 12-часов in-memory кеш по държава и година;
- резервен режим при timeout, HTTP грешка или невалиден JSON;
- настройки за работен ден, дневно време, блокове и почивки;
- автоматично сортиране на задачите по score и срок;
- разделяне на големите задачи на изпълними блокове;
- пропускане на уикенди и национални празници;
- предупреждения за задачите, които не могат да се вместят;
- записване на генерирания график в SQLite;
- Dashboard със задачи за днес, просрочени задачи и следващ блок;
- отделен напредък по брой задачи и по вложено време;
- разпределения по статус, приоритет и категория;
- седемдневен обзор на планирани и изпълнени блокове;
- автоматично отбелязване на блоковете при завършване на задача;
- общи съобщения за успешни и неуспешни операции;
- loading състояния при записване и генериране на график;
- responsive desktop и mobile изгледи;
- векторно лого със списък и молив;
- 57 автоматични теста.

## Стартиране

```bash
dotnet restore PlannerPro.sln
cd src/PlannerPro.Web
dotnet run
```

Стартирането от папката на уеб проекта гарантира, че `wwwroot` и статичните CSS/JavaScript файлове се намират правилно.
При стандартния `http` профил приложението се отваря на `http://localhost:5090`.
При първото стартиране migration-ът и демонстрационните данни се прилагат автоматично.

### Ако портът е зает

Стартирай временно на друг свободен порт:

```bash
dotnet run --urls http://localhost:5091
```

Не използваме `localhost:0`, защото Kestrel не поддържа динамично избран порт с hostname `localhost` в тази конфигурация.

## Структура

```text
src/PlannerPro.Web/       MVC уеб приложението

```

## Mock AI оценка

При всяко създаване или редактиране `PriorityScoringService` оценява:

- спешност на срока — до 45 точки;
- важност от потребителя — до 25 точки;
- ключови думи — до 15 точки;
- голям оставащ обем при близък срок — до 10 точки;
- започната задача — 5 допълнителни точки.

Резултатът е детерминиран и включва обяснение на български език.

## Външен API

Страницата `/Planner` извиква:

```http
GET https://nagerholidays.com/api/v4/Holidays/BG/{year}
```

Клиентът има timeout от 10 секунди, подава `CancellationToken`, десериализира JSON чрез `System.Text.Json` и запазва успешния резултат в паметта за 12 часа. При недостъпна услуга страницата остава работеща и показва предупреждение.

## Автоматичен график

Страницата `/Planner` приема начална дата и настройки за свободното време. Алгоритъмът:

1. изключва завършените и отложените задачи;
2. сортира по `PriorityScore` и най-близък срок;
3. създава свободни работни интервали;
4. пропуска изключените уикенди и празници;
5. разделя задачите на блокове до зададения максимум;
6. запазва блоковете в таблицата `ScheduleBlocks`;
7. показва предупреждение за всеки непланиран остатък.

„Оптимизиран“ означава практична и обяснима евристика, а не доказан глобален математически оптимум.

## Dashboard и статистика

Началната страница използва актуални данни от `Tasks` и `ScheduleBlocks`. Страницата `/Statistics` изчислява:

- завършени спрямо всички задачи;
- изпълнени спрямо прогнозни минути;
- брой задачи по статус и приоритет;
- напредък по категории;
- планирано и изпълнено време за следващите седем дни.

Визуализациите са реализирани с Razor, Bootstrap и CSS, без външна chart библиотека.
